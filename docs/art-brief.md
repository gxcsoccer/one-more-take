# 美术需求 · 第 02 场《三层楼，一只猫》（3D 版）

给负责出图的 agent（Codex 驱动 GPT Image 2.6）。游戏已改为真 3D 的桌面微缩片场：一盏真聚光灯照着发条鸭，影子由渲染直接产生。现在场景里所有东西都是用基本几何体搭的占位模型，这份文档说明要替换成什么。

现状截图在 `qa-out/`（运行 `npm run smoke` 生成），其中 `04-play-fits.png` 是布景视角，`09-dark-keeper.png` 是电影镜头视角。

## 美术方向：桌面玩具片场

- 一张木桌上搭出来的微缩电影布景，像定格动画的片场。观众应该感觉“这些东西我能用手拿起来”。
- **硬质玩具加纸板模型**：鸭子是上了漆的铁皮或塑料发条玩具；楼是彩色卡纸和瓦楞纸板糊的；居民是纸片小人；猫是关节木偶。
- 这样选是为了动画：硬质玩具只需要摇晃、弹跳、转发条，不需要骨骼动画。**不要设计需要柔软形变才成立的角色**。
- 配色：夜空青 `#0d2029` 到 `#5b8d84`，钨丝灯暖黄 `#ffdfa6`，纸板米色 `#e6d2b3`，楼层色带珊瑚橙 `#d98a5f`、姜黄 `#e8b85a`、灰绿 `#7fb5a6`，强调红 `#e9523f`。
- 新加坡组屋的气质（色带、走廊、晾衣杆），但不出现真实地标、品牌和任何文字。

**所有图片都不要画影子、光束和强烈的方向光。** 光影全部由游戏实时计算，画进贴图里会和真影子打架。

## 第 0 步：先定风格（三张图，看过再继续）

出三张**概念设定图**，不进游戏，只用来确认方向：

1. 整个片场的三分之四俯视图：桌面、纸板楼、灯轨、鸭子、场记板。
2. 发条鸭的三视图（正、侧、背），纯色背景。
3. 纸板楼正立面的材质特写：能看清卡纸纤维、切口厚度、手绘色带。

确认后这三张就是后面所有素材的风格基准，每次出图都把它们作为参考图带上。

## 第 1 批：贴图（已接入，放进去刷新即生效）

放到 `public/assets/`，在 `public/assets/manifest.json` 登记：

```json
{ "slots": { "facade": "facade.png", "floor": "floor.png", "sky": "sky.png" } }
```

| 槽位 | 尺寸 | 要求 |
|---|---|---|
| `facade` | 1800 × 1040 | 楼的正立面，正面平视无透视。**不带窗、门、招牌、人**（窗是单独的 3D 模型）。4 层，每层高 240 px，从底边往上排；顶部 80 px 是女儿墙。每层底部一条色带。整体偏亮，深色影子压上去才清楚。平光，不带阴影 |
| `floor` | 1024 × 1024 | 片场木地板，**四方连续可平铺**。俯视，木纹竖向。不要高光和阴影 |
| `sky` | 2048 × 1024 | 夜空加远处城市天际线的手绘背景板，像剧场的天幕。下三分之一是楼群剪影和零星亮窗，有一轮月亮 |

## 第 2 批：3D 模型（用 Meshy 生成）

项目负责人已有 Meshy 账号，模型用 Meshy 的图转 3D 生成。流程是：先用 GPT Image 出每个道具的参考图，再用 Meshy 的接口把参考图变成模型，下载 GLB 放进仓库。

### 哪些做成模型，哪些不做

| 道具 | 做法 | 原因 |
|---|---|---|
| 发条鸭 | **不用 Meshy**，由代码按概念图的比例用椭球搭 | 它的影子要被判定。画面和判定必须是同一套形状，见 `src/sim/light.ts` 的 `DUCK` |
| 窗、窗台 | 不用 Meshy，继续用代码画 | 28 扇一模一样的窗，方盒子足够，还省面数 |
| 聚光灯、场记板、黑猫、纸片居民、邻楼 | 用 Meshy | 不参与判定，形状细节越像概念图越好 |

### 每个模型的要求

| 模型 | 文件 | 实际大小 | 要点 |
|---|---|---|---|
| 聚光灯 | `lamp.glb` | 高 8 cm，宽 7.5 cm，长 9 cm | 轨道小车上的矮脚小聚光灯，红色搪瓷，黄铜包边和铆钉。镜片朝前，**镜片中心离桌面 4 cm**（这是模拟里光源的高度，不能高）。概念图里灯头架得偏高，请压低 |
| 场记板 | `clapper.glb` | 宽 16 cm，高 14 cm | 板面和条纹打板臂。**板面留空**，文字由游戏写。打板臂最好是可分离的一块，做不到就整体一块，由代码处理 |
| 黑猫 | `cat.glb` | 高 8 cm | 蹲坐的木偶猫，面朝前，耳朵尖，尾巴是一串木珠。黄眼睛 |
| 纸片居民 × 3 | `resident-1.glb` 到 `-3.glb` | 高 5 cm | 半身小人，三种发型或帽子。深色剪影风格 |
| 邻楼 × 2 | `block-a.glb`、`block-b.glb` | 高 30 到 44 cm | 简单的纸板盒楼，带手绘色带和小窗。只需要正面和两个侧面好看 |

第三拍的猫蹲在两列窗之间的小窗台上（第三层，从左数第五、六扇窗之间），不再有霓虹招牌，所以招牌不用做。

### 参考图怎么出

每个道具出 1 到 4 张图，喂给 Meshy 的多图接口。**第一张必须是正面**，其余是侧面、背面、四分之三视角，顺序不限。

- 纯色背景（浅灰或浅蓝），物体居中、完整入画、不裁切。
- 平光，不要投影，不要地面，不要其他物体。
- 几张图里是同一个物体、同一比例、同一配色。
- 风格对照 `docs/concept/` 里的三张定稿图。

### Meshy 接口参数

以下是第 02 场首件聚光灯的生成配置，按 2026-11-28 的官方文档核对。

| 参数 | 值 | 说明 |
|---|---|---|
| 接口 | `POST /openapi/v1/multi-image-to-3d` | `image_urls` 接受 1–4 张图，支持公开 HTTPS 地址或 data URI。正面图排第一，每张至多 20 MB |
| `ai_model` | `meshy-7.1` | 固定生成模型，方便同一批道具复现 |
| `geometry_resolution` | `standard` | 几何精度与贴图分辨率独立 |
| `texture_model` | `meshy-7` | 支持 PBR 材质 |
| `target_formats` | `["glb"]` | 只导出游戏接入所用格式 |
| `should_remesh` | `true` | 不重拓扑的话面数不受控 |
| `topology` | `triangle` | |
| `target_polycount` | 灯 6000；猫 5000；场记板 2000；居民每个 800；邻楼每栋 800 | 见下方“面数预算”，按出镜的个数算 |
| `should_texture` | `true` | |
| `enable_pbr` | `true` | 需要金属度和粗糙度贴图，搪瓷和黄铜才有区别 |
| `texture_resolution` | `2k` | 下载后贴图缩到 1024，每个 GLB 控制在 1.5 MB 以内 |

[Meshy 多图转 3D 参数](https://docs.meshy.ai/en/api/multi-image-to-3d)

调用和下载

- API 需要支持该功能的付费套餐和预充值的 API 额度。表中模型配标准几何、2K 贴图时每次 30 点，纯网格 20 点。8 件各做一次为 240 点，各做三次为 720 点。先做首件可以用 30 点验证比例、材质和接入效果。[套餐](https://help.meshy.ai/en/articles/15696428-what-is-included-on-the-free-plan) · [API 计价](https://docs.meshy.ai/en/api/pricing)
- 普通 API 任务的文件最多保留 3 天。任务到达 `SUCCEEDED` 后下载 `model_urls.glb` 和 `thumbnail_url`，签名链接的有效期以任务的 `expires_at` 为准。[文件保留和链接有效期](https://docs.meshy.ai/en/api/asset-retention)
- 密钥在 https://www.meshy.ai/developers/keys 创建，建议给它设一个每月额度上限。密钥只放在本机的环境变量里（例如 `MESHY_API_KEY`），**不要写进任何文件、提交记录、PR 或聊天消息**。

### 交付

- GLB 放 `public/assets/models/`，文件名按上表。每个模型附一张 Meshy 返回的预览图，放 `docs/art-prompts/previews/`。
- 提示词、参考图和用到的接口参数记在 `docs/art-prompts/`。
- 模型的朝向、原点、缩放不用手工调：接入时由代码按“实际大小”一栏把模型缩放到位，并把底面中心对到桌面。模型交付时标明正面朝向。聚光灯额外标出镜片中心，以便接入时对齐模拟光源。
- 游戏里加载 GLB 的代码还没写。第一个模型到了以后，由我在同一个 PR 里接入并验证。

### 接入时怎么验收

鸭子：它的椭球已经按概念图重做过（`src/sim/light.ts`）。钥匙在判定里是实心的，概念图里的两个孔没有做，因为孔会漏光、让画面和判定对不上。以后如果换成外部模型，必须把侧视轮廓叠在现有椭球上核对头顶、嘴尖、腹部和钥匙，并用三拍各自的目标布景和刚好过关、刚好失败的布景比较实拍与判定，尤其要看猫落在影子边缘时两者是否一致。[关卡参数](../src/game/scene02.ts) · [鸭子轮廓](../src/sim/light.ts)

灯：轮子接触面落在桌面后，测量 GLB 的镜片中心。整灯高 8 cm 时，镜片离桌面必须是 4 cm，横向对准轨道中心，并与模拟光源的深度对齐。如果导出的灯身比例有偏差，调整灯身在底盘上的安装位置，再复测。灯的模型不投影（否则会挡住自己的光）。

立面保留平整的受影面，纸纤维和手绘色带进入贴图。

## 第 3 批：界面与图标

| 内容 | 尺寸 | 要求 |
|---|---|---|
| 应用图标 | 1024 × 1024 | 鸭子的巨大影子投在纸板楼上，不透明底，不带字 |
| “CUT!” 与 “KEEPER!” 字样的底板 | 1600 × 600，透明 | 只要手写粉笔或油漆质感的底板和装饰，**字由游戏写** |
| 标题画面 | 2732 × 2048 | 片场全景，上方留出放标题的空位，不带字 |

## 交付与验收

1. PNG，sRGB，8 位。贴图不透明；界面元素真透明背景。
2. 文件名、尺寸与上表一致。每批的提示词存到 `docs/art-prompts/`。
3. 贴图放进去后运行 `npm run smoke`，全部通过，并检查 `qa-out/` 里的截图：影子在灯最远和最近时都清晰，贴图没有接缝、白边和画进去的阴影。
